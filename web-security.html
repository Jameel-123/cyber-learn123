Web Security

Web security focuses on protecting websites, web applications, and online services from attacks and unauthorised access.

Because many organisations rely on web applications, web security has become one of the most important areas in cybersecurity.

Authentication

Authentication is the process of verifying a user’s identity.

Common authentication methods include:

  • Usernames and passwords
  • Multi-factor authentication (MFA)
  • Biometrics
  • Security tokens
Example: Username + Password + Verification Code

Authorisation

Authorisation controls what users are allowed to access after they have successfully logged in.

Different users may have different permissions.

  • Admin users
  • Standard users
  • Guest users

Session Management

Session management keeps users logged in while they move between pages of a website.

Poor session handling can allow attackers to hijack accounts.

Example: localStorage is used in this prototype to simulate login sessions.

Input Validation

Input validation checks user input before it is processed.

Without validation, attackers may inject harmful data into applications.

  • Checking input length
  • Removing dangerous characters
  • Restricting invalid input types

SQL Injection

SQL Injection occurs when attackers inject malicious SQL commands into database queries.

Poorly protected applications may allow attackers to read or modify database data.

Applications should validate and sanitise input to reduce SQL Injection risk.

Cross-Site Scripting (XSS)

XSS occurs when attackers inject malicious scripts into web pages viewed by other users.

XSS can be used to:

  • Steal session information
  • Redirect users
  • Modify page content
  • Run malicious scripts

HTTPS and Encryption

HTTPS encrypts communication between users and websites.

Encryption helps protect sensitive information such as passwords and personal data.

HTTP = Unencrypted HTTPS = Encrypted

Secure Design Principles

Secure applications should be designed with security in mind from the beginning.

  • Least privilege
  • Strong authentication
  • Input validation
  • Secure session handling
  • Regular patching
