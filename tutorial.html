Tool Tutorial Overview

This tutorial explains how to use Jameel’s Cyber Tool and what each module inside the toolkit does.

The tool is designed for educational and authorised cybersecurity testing only. It helps users understand scanning, services, banners, processes, file hashing, and report handling.

Only use this tool on systems you own or have permission to test.

Step 1 - Opening the Tool

First, download the toolkit ZIP file from the Download Tool page. Extract the ZIP folder, then open the extracted folder in Visual Studio Code.

File → Open Folder

Once the folder is open, press the Run button in Visual Studio Code. The graphical toolkit window should open.

Port Scanner

The Port Scanner checks whether a port, or a range of ports, is open on a target host. This helps users identify which network services may be exposed.

The key part of the code is:

def scan_ports(host, ports_text):

The scanner uses a socket connection test. If the connection succeeds, the port is treated as open.

result = s.connect_ex((host, port)) return result == 0

The function returns the target and a list of open ports.

Open ports are not automatically vulnerabilities, but they show what services may be reachable.

Service Checker

The Service Checker maps common port numbers to likely service names. For example, port 22 is usually SSH, port 80 is HTTP, and port 443 is HTTPS.

def get_service_name(port):

The module uses a dictionary of common ports and services.

22: "SSH" 80: "HTTP" 443: "HTTPS" 3389: "RDP"

This helps users understand what a detected open port may be used for. If the port is not in the dictionary, the tool returns “Unknown”.

Banner Grabber

The Banner Grabber connects to a target service and tries to read information sent back by that service.

def grab_banner(host, port, timeout=2):

For web ports such as 80, 8080, and 8000, the tool sends a simple HTTP HEAD request.

request = "HEAD / HTTP/1.0\r\n\r\n" s.send(request.encode())

The important command that receives the banner is:

banner = s.recv(1024)

Banners can sometimes reveal software names, versions, or service details.

Exposed banner information can help attackers during reconnaissance, so unnecessary banner exposure should be reduced.

Process Viewer

The Process Viewer lists running processes on the local machine. This helps users understand what applications and background services are active.

def list_processes():

The main command loops through running processes and collects the process ID and process name.

for process in psutil.process_iter(["pid", "name"]):

This module can help identify suspicious or unfamiliar processes during basic system review.

File Hasher

The File Hasher creates a cryptographic hash for a selected file. Hashes are useful because even a small change to a file will produce a different hash value.

def hash_file(file_path, algorithm="sha256"):

The tool reads the file in chunks instead of loading the full file at once. This is better for larger files.

chunk = file.read(4096) hash_object.update(chunk)

The final hash is produced using:

hash_object.hexdigest()

File hashing is useful for checking integrity, detecting modification, and supporting digital evidence handling.

Report Viewer

The Report Viewer allows users to open and review reports generated by the tool.

Reports are saved locally inside the tool folder, usually inside a folder called:

reports

An example report name may look like:

reports/report_88_20260524_211612.json

These reports may contain scan results, detected open ports, service information, banner output, hashes, and other generated findings.

Upload Report

The Upload Report feature demonstrates how a generated report could be sent to a future web platform.

The upload window includes an API key field. An API key is like a secret access code that a real backend system would use to confirm the tool is allowed to upload data.

In the current GitHub Pages version, reports are not permanently uploaded because GitHub Pages is a static website and does not include a backend database or file storage system.

This upload feature is currently a prototype workflow. A full version would require a backend API, secure authentication, and database or cloud storage.

Ethical Usage

This toolkit should only be used in authorised environments. The purpose of the tool is to support learning, awareness, and safe cybersecurity practice.

  • Do not scan systems without permission.
  • Do not attempt to misuse discovered services.
  • Use results for learning, reporting, or defence.
  • Store reports responsibly.
Unauthorised testing may be illegal.
